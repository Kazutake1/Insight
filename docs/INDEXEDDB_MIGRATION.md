# InsightのIndexedDB移行設計

## 調査結果

基準は main `3bfd2eb004ed59dd4f800b928ef8109e6b4a46a6`。復元保護と容量診断の統合候補は Draft PR #319 の `4f5e3719fd37bbec6746fb45917f880a94f0cd5e`。#319 の回帰64ジョブとCodeQLは成功し、独立レビューはコードと自動検証の範囲で合格。統合版のiPad確認は未実施。根拠は Issue #211 の #6817927401。

| 経路 | 現状と移行時の扱い |
| --- | --- |
| 起動 | `insight_payload_core_v1.js` は `insight_v11` を同期読み込みし、不正データでは起動を止める。v11がない場合はv9/v8の読み込み経路もある。既存の起動前検証を非同期の保存先選択より後、画面起動より前に置く。 |
| 主データ | `current` と `stores` を持つJSON。店舗内に年度リストと年度・月・日別データがあり、共有天気や設定など店舗外の属性もある。未知の旧フィールドも含め、移行時の照合は文字列全体の完全一致で行う。 |
| 通常保存 | `insight_storage_v1.js` の `writeSnapshot` / `persistCurrent` / `transaction` が共通経路。旧payloadには直接書くフォールバックもある。保存前に古いタブを検出する処理がある。移行前にすべての有効な呼び出し経路とキャッシュ混在時のフォールバックを棚卸しする。 |
| 別キー・参照 | ダーク設定やバックアップ時刻は別キー。保存済みレポートはlocalStorageを直接参照する。容量診断・復旧書き出し・他タブ通知を含め、主データを直接読む経路は保存先切替時にまとめて対応する。主データ以外の設定は当面そのまま利用する。 |
| バックアップ・復元 | mainの `insight_backup_guard_v1.js` は既存JSONを正規化し、#319は暗号化バックアップ、復元前確認、容量診断、保存失敗の保護を追加している。ファイル形式は継続し、復元先だけを保存処理の共通経路に通す。 |
| 発注予測 | `insight-forecast-pilot-v1` の `captures` は別のIndexedDB。経営データ用DBの作成・移行・復旧ではこのDBを開いたり変更したりしない。 |
| 容量 | Issue #211の #6740076369 によると、架空JSON約2.48 MiBは旧iPad検証で容量不足。正規化で欠けていた廃棄カテゴリが補われ、UTF-16の参考換算で候補だけでも約5.05 MiBになった。換算値はブラウザーの実測上限ではない。 |

## 実装順序

1. **コピーだけを検証する。** 元の文字列を読み取り、新規の専用DBに候補として追加する。候補を同一トランザクション内で上書きさせず、コミット後に別の読み取りトランザクションで全体を再照合する。元の再読と外部更新通知を組み合わせ、変化があれば停止する。同一の候補は再利用できる。異なる候補は保持したまま競合として停止する。
2. **試験環境でアプリの保存経路を切り替える。** 起動時にIndexedDBを非同期で読み、既存の画面・集計処理には従来と同じオブジェクトを渡す。店舗をまたぐ共有更新、年度変更、復元を含む保存はまずスナップショット単位で扱う。新規専用DBのトランザクション内で基準リビジョンを照合し、新リビジョンと直前版を原子的に確定する。競合・容量不足・中断時は直前版と未保存入力を区別し、コミット成功後にだけ画面へ保存済みと通知する。
3. **旧タブ・キャッシュと復旧を検証する。** localStorageとIndexedDBをまたぐ原子的な切替はできない。旧タブや旧PWAが残ったまま本番切替する方法は採用せず、切替直前の再照合と旧版からの書き込み防止を試験する。切替後にIndexedDBが欠落した場合、古いlocalStorageを現行データとして自動採用せず、保存を止めて復旧へ案内する。ブラウザーが保存領域全体を削除するケースに備え、端末外へ退避できる既存の暗号化バックアップを維持する。
4. **架空データとiPadで判定する。** 2店舗・複数年度、過去編集、バックアップ形式2種、大容量、容量不足、書き込み失敗、中断、複数タブ、オフライン再起動、Chromium/WebKit、11インチiPad Safari/PWAを検証する。アプリ側試作はレビュー済みGATE-3保護と整合を取る。公開前にデータの整合性と復旧手順を確認し、本番切替は明示承認後とする。

## 今回の試作範囲

テスト専用ページで架空の2店舗・複数年度と約2.6 MBの追加フィールドを持つ原文をコピーする。アプリの起動処理から読み込まれず、`insight_v11` と他の保存先への書き込みは行わない。書き込み要求後の元データ変更、同一データの再試行、候補の競合、不正JSON、IndexedDBを開けない場合を検査する。実際の端末での容量不足、強制終了、アプリ保存先の切替は後続検証とする。
