# 保存時点の定型報告

既存の分析AIを維持し、サイドバーから任意に開く読取専用の報告を追加する。店舗・全期間・数量カテゴリーを明示して生成し、保存済みsnapshotだけを読む。報告を保存・送信せず、モデル・自動調査・発注を呼ばない。

- 計算エンジンは insight-ai-lab main d732aa51b78bbdd17dbc71765f8bed903eb98729 の insight_report.js を無改変で insight_report_v1.js に配置した。
- 店舗ID/名称を置換しない。カテゴリーを先頭候補で補完しない。入力状態不明のKPI保存0と、便別の明示0は別扱い。
- 比較条件の独立した確認根拠は未接続のためcomparison_confirmed:falseのみ。今回も既存capture経路を使用し、KPIの比較は確認済みにしない。参考平日平均だけ、明示採用した同梱暦の確認範囲をcalendar_bookへ渡す。既存画面の計算祝日を根拠へ転用せず、値・不足情報・全件の事実を保持する。
- JSONは各2,000,000 UTF-16コード単位、深さ32、値ノード100,000、設定店舗16まで。上限超過や破損は切り詰めたり修復・保存せず報告を保留する。実データの全サイズで利用可能とは保証しない。
- 店舗名重複は現エンジンの識別制約で拒否する。設定・報告は要求ごとに独立し、閉じると旧本文を消す。
- 読取前後の保存rawと条件を照合し、保存層のrevision/pending/held/conflictも確認する。readSnapshotの移行処理、ensure、保存、初期化を報告の入力取得に使わない。
- writeSnapshotの内部入口、persistCurrent、transactionのmutate/validate/apply全体、writeMetadataで本体保存キーを書く場合に通知する。通常のmetadataは対象外。通知例外は既存保存に伝播させない。保存の戻り値・例外・保存形式を維持する。
- 保存開始で本文を消す。保存・適用中の生成は読取前に止め、失敗後はページ再読込まで保留する。後からの成功で失敗を追認しない。別タブ更新・clearも再読込まで保留する。通知の欠落をrevisionだけで完全検知できるとは扱わない。
- 後続フックがさらに保存した場合も各保存開始で消す。非同期操作全体の自動完了監視は未実装であり、報告は明示生成した保存時点の値である。自動再生成・最新値の保証はしない。
- 報告内の条件変更、外側の操作、ページ再表示、可視状態変更、JST日付変更で旧本文を消す。本文と店舗名はtextContentで表示し、実値をログやファイルへ出さない。
- 既存画面・分析AI・保存形式・insight_v11・外部記憶は変更しない。追加CSSは報告dialogだけに限定する。

検証は架空2店舗のみ。単体で通知の例外分離、private write、apply中待機、保存失敗、比較保留、保存0と便0を確認し、Chromium/WebKitで生成・条件変更・未保存live除外・保存中/失敗/外部更新・文字表示・11インチ横向き相当のライト/ダークを確認する。既存回帰と公開ファイル検査も実行する。実機iPad・実店舗データ・需要予測・本番の優先順位や閾値は未検証。
