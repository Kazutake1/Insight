# IndexedDBの保存停止後に確認する内容

Draft #341の隔離環境で、診断は保存停止中の採用記録、IndexedDBのレコード、移行元の `insight_v11` を読み取る。保存停止中に診断を繰り返すことができる。

| 診断結果 | 照合できた内容 | 手動復旧画面での扱い |
| --- | --- | --- |
| 移行コピーを確認 | 移行時の識別子、初版の原文、現在の移行元が一致 | コピーを確認した時点と移行元を表示する |
| 保存を確認 | 操作ID、版番号、候補と直前版のダイジェストが一致 | 現在版と直前版を区別して表示する |
| 保存前の版を確認 | 現在版が中断した操作の開始時点と一致 | 保存前の版が残っていることを示す |
| 照合不能、記録欠落、診断中の変更 | コピーまたは保存結果を確定できない | 保存停止を継続し、既存の暗号化バックアップの確認に案内する |

再開操作を接続する際は、本人が保持する内容と暗号化バックアップを確認し、再開を明示的に選択する。選択後に排他ロックを取得し、確認時の採用記録、移行元原文、版番号、現在版と直前版を再照合する。確認後に変更を検出した場合は保存停止を継続する。旧版タブや旧PWAとの競合を制御できる状態を、公開前に別途検証する。

このDraftの状態遷移は診断による確認まで。診断では採用記録やデータを変更せず、各結果で保存停止を維持する。

## 復旧画面の案

最初に保存停止を表示し、確認できた現在版・直前版の版番号と、対象の店舗・年度を表示する。「暗号化バックアップを確認」「閉じる」を用意し、確認できる版が一つに定まった場合だけ「この版で保存を再開」を提示する。選択時に表示した版の識別子・各原文・採用記録を照合し直す。旧版タブやPWAと同時実行できる間は、診断までを提供する。DBと採用記録の両方が消えた場合は履歴を確定できないため、移行元が残っていても既存バックアップの確認へ案内する。本番でこの状態を初回と区別する仕組みが必要となる。

## 移行前に確認する操作

| 操作 | Draftでの検知 |
| --- | --- |
| 今日の入力、売上・客数・廃棄、販売数入力 | 画面の未保存状態と保存済み原文を比較 |
| イベント、カテゴリー、店舗・年度、廃棄予算 | 開いているダイアログ、店舗メニュー、年度追加欄を検知 |
| CSV取込、天気・気温取得、天気地点検索、過去の天気の一括取得 | 読み込みや取得の終了まで待つ |
| 暗号化バックアップ、復元 | 実行中と復元後の保存停止を検知 |

設定画面や今後追加する操作について、ダイアログを使わず未保存値を保持する経路と、画面遷移後も続く処理は、各保存入口をIndexedDBへ接続するときに個別に照合する。
